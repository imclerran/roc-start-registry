# roc-start Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the `imclerran/roc-start-registry` repository that publishes `releases.json`, `templates.json`, and stub-app templates to GitHub Pages for the rewritten roc-start.

**Architecture:** Two hand-maintained CSVs and a templates directory are the inputs. A stdlib-only Python script crawls the GitHub Releases API once per night in Actions, filters assets by the new compiler's bundle filename, and commits the JSON outputs to `gh-pages` only when they changed. A second script validates PRs. No Roc toolchain runs in CI.

**Tech Stack:** Python 3.12 standard library only (`csv`, `json`, `re`, `urllib`, `unittest`, `pathlib`), GitHub Actions, GitHub Pages, `gh` CLI for one-time setup.

**Spec:** `docs/superpowers/specs/2026-11-13-registry-design.md` (in roc-start on the `new-compiler` branch; Task 1 copies it into the new repo).

## Global Constraints

- The new repository is `imclerran/roc-start-registry`, created locally at `~/Projects/roc-start-registry`. Canonical Pages URL: `https://www.imclerran.com/roc-start-registry/` (the owner's custom domain; `https://imclerran.github.io/roc-start-registry/` redirects there).
- No third-party Python packages. Everything must run with `python3 -m unittest` on a stock `ubuntu-latest` runner.
- No Roc toolchain, `roc check`, build, or package download in any workflow.
- Bundle asset filter, verbatim (named groups `variant`, `hash`): `^(?:(?P<variant>[a-z][a-z0-9_]*)-)?(?P<hash>[1-9A-HJ-NP-Za-km-z]{43,44})\.tar\.zst$`. Base58 of a 32-byte digest is 43 or 44 characters. (Tasks 1–6 used `{44}`; Task 8 fixes it.) Release tags considered: `^v?\d+(?:\.\d+){1,2}(?:-[0-9A-Za-z.-]+)?$`; other tags are skipped with a warning.
- Alias rule, verbatim: `^[a-z][a-z0-9_]*$`. Repo rule: `^[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?/[A-Za-z0-9._-]+$`.
- Template tag rule: `^v?\d+\.\d+\.\d+(?:-[0-9A-Za-z.-]+)?$`. `verified-nightly` rule: `^nightly-\d{4}-\d{2}-\d{2}-[0-9a-f]{7}$`.
- Placeholders: `{{dependencies}}` exactly once per template; `{{pf}}` any number of times; no other `{{...}}` token.
- `releases.json` top-level keys are exactly `generated`, `roc`, `platforms`, `packages`. Entry keys are exactly `repo`, `alias`, `variant`, `releases` (one entry per CSV row; `variant` is the row's variant or `null`); release keys exactly `tag`, `url`, `published`. `releases` sorted newest first by `published`.
- CSV rows are `repo,alias` or `repo,alias,variant`; variant matches `^[a-z][a-z0-9_]*$`. A repo's variants are declared across BOTH files (a repo may have a platform row and a package row); the default variant is its first row in `platforms.csv`, else its first row in `packages.csv`. A repo with any variant row may not also have a variant-less row in either file; `(repo, variant)` is unique across both files. `bundles.csv` rows are `repo,tag,hash,variant`, variant declared in either file.
- Bundle identification rules (spec, "Bundle identification"), verbatim order: (1) no variant rows → exactly one bundle, else unresolved; (2) one BARE bundle with variant rows → default variant; (3) a prefix names a declared variant, an undeclared prefix → unresolved even for a single bundle; (4) bare hash → `bundles.csv` lookup by `(repo, tag, hash)`; (5) at most one bare hash without a row → default variant, two or more → unresolved; (6) two bundles on one variant → unresolved. Unresolved releases are omitted and reported with repo, tag, and reason. The tracking issue lists only unresolved releases newer (by `published_at`) than the repo's newest resolved release.
- `templates.json` keys are exactly `generic` (value `templates/generic.roc`) and `templates` (repo → list of `{ "tag": str, "requires": [repo, ...] }` sorted by tag ascending).
- Requires line, verbatim: `^# requires: ([A-Za-z0-9._-]+/[A-Za-z0-9._-]+)(, [A-Za-z0-9._-]+/[A-Za-z0-9._-]+)*$`; if present it must be line 1 of the template, and every repo it names must be a row in `packages.csv`.
- Every platform's alias is `pf`, the ecosystem convention. Package aliases are unique within `packages.csv`.
- Commit messages are plain imperative sentences and end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **Draft and prerelease releases.** Drafts must never appear; prereleases must appear, because packages such as roc-parser ship `6.0.0-rc.2` that way. Pinned in Task 3 (`test_build_entry_skips_drafts_keeps_prereleases`).
2. **A release with several bundles.** Each bundle is assigned by prefix or `bundles.csv` row, never by order or release-notes text; anything ambiguous is omitted and reported rather than guessed. Pinned in Task 6 (`test_identify_*` and `test_build_entries_unresolved_*`). Tasks 3–4's `pick_asset` heuristic is removed by Task 6.
3. **CSV files edited on Windows or by hand.** CRLF endings, trailing spaces, blank lines, and the header row must all parse and validate. Pinned in Task 2 (`test_csv_crlf_and_whitespace_ok`) and Task 3 (`test_read_rows_tolerates_crlf_header_blank`).
4. **One repository failing to fetch** (404 after deletion, 403 rate limit). The job must still publish, with that entry's `releases` empty and a warning on stderr. Pinned in Task 3 (`test_build_releases_fetch_failure_gives_empty_entry`).
5. **A quiet night.** When nothing upstream changed, the outputs must be byte-identical to the previous publish so no commit happens; in particular `generated` must be carried over. Pinned in Task 3 (`test_write_outputs_unchanged_keeps_generated_and_returns_false`).
